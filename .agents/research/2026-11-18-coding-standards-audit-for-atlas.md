## 1. Problem and constraints

OpenDash already has an explicit baseline: `opendash-core` stays framework/I/O-free; `storage/*` owns SQLite queries; `routes/*` handles HTTP guards, decoding and responses; domain services coordinate workflows; React Admin uses the shared HTTP client; authentication, CSRF and data/provider ownership remain mandatory. `cms/scripts/check-standards.py` enforces part of this contract. **Keep these boundaries and the existing Rust + SQLite + embedded Admin + Wasmi stack.**

The audit found behavioral regressions that static typing and the current checker do not catch, plus gaps between the written coding standards and the checks actually required by CI. Because current delivery priority is macOS Usable Beta, any proposed implementation must be reconciled with active Harbor/Aster ownership and the existing Beta remediation queue. A research note alone does not create a Project `Ready` issue or override Beta gates.

## 4. Suggested rollout and acceptance boundaries

1. **Data isolation and user-facing correctness (earliest review):** CS-01, CS-02, CS-03, CS-04. Reconfirm each against the current `main` and current Beta issues before opening new tasks; test real navigation and same-tab account switching. Treat CS-01 as a confidentiality concern and CS-03/04 as potential authored-content loss/corruption. Do not infer a production security incident from code inspection.
2. **Standards enforcement:** CS-05 and CS-06. First make the checker measure coverage and CI fail meaningfully; then submit a formatting/Clippy-only baseline PR separately from behavior changes. Add frontend linting with no mass dependency bump; match the repository's pinned toolchains.
3. **Focused functional hardening:** CS-07, CS-08, CS-10, CS-11, CS-12. Test each with a deterministic failing-case fixture, including failed API/reload/auth scenarios.
4. **Architecture cleanup:** CS-09, CS-13. Prefer small PRs with behavior-preserving contracts. Defer overlapping modules until Aster/Harbor slot and file ownership are explicitly available.

For any implementation Issue: pin approved source/base SHA, exact file owner and dependency, G3 or required task gate, before/after behavior, reproduction/acceptance, safe rollback and platform-specific verification. `cargo fmt`/Clippy cleanups must not silently rewrite or claim to resolve historical security/release failures. Windows evidence does not substitute for macOS Usable Beta retests, and Beta evidence does not substitute for common RC/V1 native gates.
