## 1. Problem and constraints

OpenDash already has an explicit baseline: `opendash-core` stays framework/I/O-free; `storage/*` owns SQLite queries; `routes/*` handles HTTP guards, decoding and responses; domain services coordinate workflows; React Admin uses the shared HTTP client; authentication, CSRF and data/provider ownership remain mandatory. `cms/scripts/check-standards.py` enforces part of this contract. **Keep these boundaries and the existing Rust + SQLite + embedded Admin + Wasmi stack.**

The audit found code paths for functional regressions that static typing and the current checker do not catch, plus gaps between the written coding standards and checks required by CI. The F01–F09 / #318–#326 Beta remediations are **closed** as of Aster's 2026-11-18 review; do not treat them as an active coding queue. Current priority is the Content Foundation slices under Aster coordination and Harbor implementation; overlap with #374/C2 (Draft PR #383), #375/C2 UI, #376 resolver and #378 provider bridge must be checked again when scheduling. Research status does not create a Project `Ready` issue or override any gate.
