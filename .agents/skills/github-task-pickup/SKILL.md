# Nhận task thủ công từ GitHub Issues

- Chạy **một lần trong lượt chat hiện tại** khi người dùng yêu cầu lấy/làm task; không tự lên lịch, không gọi Task Watcher, không lặp nền, không gửi input tới CoS Local Control API.
- Đọc repo [AGENTS.md](../../../AGENTS.md), [Agent Operating Standard](../../AGENT_OPERATING_STANDARD.md), [GitHub workflow](../../GITHUB_WORKFLOW.md), [agents.yaml](../../agents.yaml) và metadata Git của **workspace đang thao tác**. Định danh agent bằng ngữ cảnh người dùng + worktree + cấu hình (ví dụ Forge ⇒ label `agent:forge`, branch `agent/forge`); nếu không xác minh được, chỉ đọc và báo thiếu định danh. GitHub account `thientran2359` được nhiều agent sử dụng, **không đồng nghĩa với vai trò Forge**.
- Nguồn active task: **GitHub Issues và Project #3 Status**, không phải `.agents/tasks/`. Issue mô tả scope; G3/contract đã duyệt trên `origin/main` tại SHA nguồn là tiêu chuẩn kỹ thuật; PR quản lý thay đổi/review. Ưu tiên GitHub Connector đã kết nối; nếu thiếu công cụ truy cập Project v2, dùng GitHub API/CLI đã xác thực hoặc **CoS Desktop Browser attach Chrome đúng tài khoản đã đăng nhập** theo Operating Standard. Không dùng Plugins Browser profile riêng để suy ra trạng thái đăng nhập. Không yêu cầu token trong chat, không lấy token từ transcript, không in secret.
- Giữ các khóa bảo vệ hiện hành: **một implementation task active/agent branch**, không ghi đè thay đổi chưa commit, không tự merge/deploy/đánh dấu VERIFIED, không tự sửa ACL/credentials.

## Quy trình nhận task

1. **Kiểm tra công việc đang dở trước:** đọc `git status`/branch/remote, Issue/Task ID và các PR đang mở của agent. **Phân nhánh bắt buộc:** `RESUME_CURRENT` khi có Issue đang `In progress` hoặc `In review`/PR của **chính task đã nhận**; chỉ xét `PICK_NEW` khi không còn task/PR chiếm branch. PR khác hoặc thay đổi chưa rõ chủ sở hữu ⇒ `BLOCKED`, không đổi task/branch để né.
2. **Tìm và đối chiếu Issue của chính agent:** tìm Issues **open** trong `thientran2359/opendash-cms` có **đúng** label `agent:<current-agent>` (ví dụ `repo:thientran2359/opendash-cms is:issue is:open label:agent:forge`), đọc đủ Issue bằng `fetch_issue`, comments, Project status và PR liên quan. Tách Issue research/coordination khỏi implementation. Không coi label hay GitHub account chung là bằng chứng đã được giao.
3. **Nhánh `RESUME_CURRENT` — tiếp tục task đã nhận, KHÔNG yêu cầu `Ready` hoặc worktree sạch:** xác minh cùng Issue/Task ID, agent/branch, approved `source_sha`/`base_sha`, ownership, dependency/security gate **phù hợp với hành động sắp làm**, trạng thái thực `In progress` hoặc `In review`, PR head và feedback mới nhất. Cho phép file dirty **chỉ khi đã xác minh từng thay đổi thuộc chính task này** (kiểm `git status/diff`, file ownership, không ghi đè dữ liệu agent khác). Nếu `In progress`, tiếp tục đúng phạm vi Issue; nếu `In review` có feedback cần sửa, sửa **trên chính PR/branch đó**, kiểm thử và push non-force theo workflow. **Giữ nguyên status `In progress`/`In review`**, tuyệt đối không kéo ngược về `Ready` chỉ để qua gate. Nếu chỉ chờ review/approval hoặc security gate chưa cho phép hành động yêu cầu, báo `WAITING`/`BLOCKED`; không lấy task mới. PR/dirty changes không thuộc task hoặc không xác minh được ⇒ `BLOCKED`, không tự stash/reset/force.
4. **Nhánh `PICK_NEW` — chỉ nhận implementation task mới khi không có task/PR đang chiếm branch:** Project [#3](https://github.com/users/thientran2359/projects/3) phải xác minh **Status = Ready** qua GitHub Project v2 hoặc UI có quyền (không suy từ label/body); **worktree phải sạch (không có thay đổi chưa commit)** và **không có PR khác đang mở trên branch**. Nếu dirty thì `BLOCKED`, không tự stash/reset. G3/Full-Track G2 tại immutable `source_sha` đã merge, `base_sha`, Issue 8 mục, dependency đạt đúng gate/evidence, owner và file ownership đều hợp lệ. Project không đọc được (ví dụ thiếu `read:project`), sai status/phân trang, thiếu source hay blocker ⇒ `BLOCKED/NEEDS_VERIFICATION`, **không nhận**. Không áp dụng yêu cầu `Ready`/clean của bước này ngược sang `RESUME_CURRENT`.
5. **Thực hiện:** ưu tiên `RESUME_CURRENT` trước mọi task mới; sau đó chọn own task `Ready` hợp lệ theo Project priority đã chứng minh (nếu có), rồi thời điểm tạo/Issue number. Khi người dùng nói **"lấy task của mình về làm"**, có thể tiếp tục/nhận đúng Issue đủ gate **không cần hỏi lại**; báo Issue #, scope, branch, SHA, bước thực hiện và test. Re-fetch trạng thái ngay trước thao tác ghi, không ghi đè agent khác. Chỉ cập nhật `In progress`/comment nhận việc **khi PICK_NEW** theo workflow/quyền; `RESUME_CURRENT` giữ status và PR hiện tại. Không tự đánh dấu `Done`/merge/deploy.
6. **Nếu không có task của agent có thể làm và branch không bị chiếm:** tìm candidate **chưa giao hoặc đang được agent khác sở hữu (chỉ để đề xuất chuyển giao)** trong cùng repo: open, Status `Ready` được xác minh, G3 merged và dependencies clear, phù hợp vai trò và file ownership. Đưa **tối đa 3 đề xuất** có Issue link, task owner hiện tại, giá trị/phạm vi, dependency, rủi ro/branch conflict. **Coordinator Atlas/Nova (hoặc agent được giao điều phối) quyết định phân công cuối cùng theo [ADR-0003](../../../docs/decisions/ADR-0003-agent-consensus-governance.md)**; nếu candidate đang có owner khác, cần current task owner/coordinator giải phóng ownership và cập nhật Project trước. Owner theo dõi tiến độ, không phê duyệt pickup theo từng Issue. Không tự đổi `agent:*`, assignee, Project Status hoặc bắt đầu coding khi handoff chưa có bằng chứng. Nếu không có candidate Ready, chuyển một đề xuất G1/G2 cho coordinator review, không tự tạo implementation Issue.
7. **Sau khi coordinator xác nhận phân công có bằng chứng trên GitHub:** re-fetch Issue, kiểm lại gate/ownership/branch theo `PICK_NEW`; coordinator hoặc agent được giao quyền cập nhật task label/Status/ownership đúng workflow. Nếu không đủ quyền/gate, báo blocker. Khi đã đủ điều kiện, thực thi theo Issue, kiểm thử, commit/push non-force rồi tạo PR cho reviewer.

**Tình huống kiểm tra bắt buộc:** own `In progress` + dirty diff đã xác minh thuộc task ⇒ `RESUME_CURRENT`; own `In review` + feedback actionable ⇒ tiếp tục sửa **chính PR đó**, không đổi status; own `In review` chỉ chờ reviewer ⇒ `WAITING`, không nhận task khác; dirty diff không rõ owner hoặc PR của task khác ⇒ `BLOCKED`; Issue mới chưa `Ready` ⇒ `PICK_NEW` bị từ chối, không ảnh hưởng resume.

## Cập nhật một file tổng hợp task khi hoàn tất

- [TASK_INDEX — danh sách 9 milestone, task và trạng thái](../../../docs/plans/TASK_INDEX.md) là **bảng tổng quan duy nhất cho người đọc**, không phải nguồn quyết định `PICK_NEW`/`RESUME_CURRENT`. Mọi trạng thái dùng để nhận task vẫn phải đọc **GitHub Issue + Project #3** theo các gate trên. `Mx-Pxx` trong index là planning candidate, **không** phải GitHub/G3 task được nhận.
- Khi **coordinator tạo task G3/Issue mới**, coordinator cập nhật hoặc giao một writer cập nhật index: giữ hàng `Mx-Pxx` gốc và thêm hàng riêng `Mx-Sxx-Txx` đúng milestone, mô tả ngắn, link Issue, trạng thái đã xác minh. Không tự tạo task ID/Issue từ index.
- Khi agent thực hiện xong phần code, commit/push và tạo PR, trạng thái tối đa là **In review** theo GitHub; không đổi index thành `Done` chỉ vì code có test PASS, PR merged hoặc Issue bị auto-closed. Có thể cập nhật hàng In progress/In review trong PR đang làm **chỉ nếu** đã được phân quyền sửa index, không có agent khác cùng sửa và Project status thực đã xác nhận; nếu không, chỉ báo coordinator đối chiếu.
- **Sau khi G5 nghiệm thu và Project Status thực chuyển `Done`**, agent/coordinator **phụ trách đóng task** phải cập nhật đúng hàng G3 trong index thành `Done`, kèm Issue/PR/evidence, sửa ngày đối chiếu ở đầu file, qua PR docs/handoff nhỏ nếu PR code đã merge. Nếu Project còn In review/Blocked hoặc không kiểm được G5, **không** ghi Done; báo `INDEX_SYNC_PENDING` với Issue link/next action cho coordinator, không giả đã đồng bộ. Nếu reopen hoặc rollback, sửa lại snapshot theo GitHub.
- Dùng **một writer** tại một thời điểm cho file index; kiểm main mới trước sửa, tránh conflict với PR agent khác. **Không** chạy polling, watcher hoặc background sync. Cập nhật file index không làm thay đổi task status trên GitHub và không thay G3/G5.

## Đầu ra mong đợi trong chat

- `CURRENT_WORK`: Issue/PR đã nhận hay branch đang chờ review.
- `RESUME_CURRENT` / `WAITING`: đang xử lý đúng task/feedback PR hoặc chờ reviewer, không áp dụng gate nhận task mới.
- `PICKED`: Issue link/Task ID, vì sao eligible, branch/source SHA, hành động thực làm, tests/evidence.
- `PROPOSED`: tối đa 3 lựa chọn kèm hành động coordinator cần chốt và liên kết GitHub; **không chờ owner xác nhận thường lệ** trước khi thay ownership.
- `BLOCKED`: gate/API/PR/branch đang thiếu, next action ngắn; tuyệt đối không nói "đã nhận" khi chưa nhận được.
- `INDEX_SYNC`: khi task đã đủ G5/Project Done, ghi link commit/PR cập nhật [TASK_INDEX](../../../docs/plans/TASK_INDEX.md), hoặc `INDEX_SYNC_PENDING` nếu phải giao coordinator; không dùng một dòng `Done` trong file làm bằng chứng nghiệm thu.
