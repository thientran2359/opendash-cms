## Overview and Goals

Complete the missing unsaved-preview contract for shared site templates in [Theme S02](theme-format-and-template-resolver.md). This is separate from the entry-owned Page preview in [D02](s02-target-only-page-builder.md). The user asks Aster to resolve Harbor's #427 blocker and complete review/handoff without repeated section gates. No product scope, schema, dependency, publication policy, legacy conversion or compatibility layer changes.

The typed API currently defines list/save/reset only. BuilderWorkspace still has an old role/scope preview caller. Save-and-undo cannot implement Preview because Save commits public templates and media refs. Preview must render the submitted AST directly in memory, including a new target with no DB row.

## Technical Plan

### Request, response and guards

Add `POST /api/admin/template-overrides/preview`. Require `require_admin_with_csrf`; anonymous 401, authenticated Editor 403 and invalid CSRF/Origin 403 under existing guards. It is read-only: no AdmittedMutation, SQL writes, hooks, registry/provider mutations, filesystem writes, saved-version increments or public media ACL/ref updates. Do not call Save and rollback, Save and reset, loopback HTTP, or the old preview endpoint.

Strict JSON body `{target: TemplateCandidate, document: BuilderDocument, preview_entry?: {type_key: string, entry_id: positive integer}}`; omitted/null preview_entry means no selected entry. Nested DTOs reject unknown fields. Accept only application/json (415 otherwise), cap the entire request envelope at 256 KiB before JSON decoding (400 if oversized within the existing HTTP body limit; transport body-limit 413 remains applicable to larger bodies). Reject invalid JSON, target dimensions/canonical key, AST, context combination or media/part graph with 400. Missing context entry returns 404 without substituting another entry. Use existing ApiError; persist nothing on any failure.

Optional `If-Match: "vN"` uses the existing typed-template parser (N>=1). If supplied, the exact canonical target row must exist at version N or return 412; no header permits a preview without a CAS precondition. Preview never requires 428 and does not mutate CAS. A malformed supplied header returns 400. A preview of a newly created in-memory target needs neither row ID nor fake DB insertion.

Return 200 JSON `{html: string, diagnostics: BuilderDiagnostic[]}` using existing `RenderedLayout` serialization; no new serialized contact-form flag, CSS field, ETag or saved-source claim. Headers: Cache-Control no-store and X-Content-Type-Options nosniff. Contact form markup is disabled using is_preview=true, preserving existing private media preview and opaque sandbox behavior. Enforce the existing render/sanitize/C-SEC pipeline; no executable client markup/HTML is accepted in the body.

### Context and exact render semantics

Preview is the edited template/component itself, not a public URL screenshot. Always render the submitted root even if a more specific saved/theme candidate would win on a public route. Do not run the public resolver to replace the root. Keep canonical target validation and the SAME target-dependent slot, route-binding and inactive-block rules as `save_typed_override`. Load only the saved row of that exact target as prior AST for inactive-block validation. Refactor common read-only validators instead of duplicating or weakening them.

| Target | Optional preview_entry rule |
| --- | --- |
| home, page, page_layout | When supplied it must name type_key=page. It need not already be assigned to that template/layout; this previews a proposed shared template. |
| single | When supplied its type must match target.content_type if present; its ID/slug must match target.entry_id/selector_slug if present. For an ID-scoped target with omitted preview_entry, derive its exact type+ID from the target and validate existence. For a slug-scoped target with omitted preview_entry, look up the exact type+slug; absent entry returns 404. Never use an unrelated row. |
| single_custom, singular | When supplied it must be non-page/non-section. For single_custom, when an active theme declaration for custom_key exists, require its allowed_types includes the selected type; a missing declaration may still preview a site-owned template, without changing resource availability or assignments. |
| index | Any supplied entry must be an eligible non-section entry. This selects private sample content, not a new route. |
| archive, taxonomy, not_found, part | preview_entry must be omitted/null; route-dependent sample entry is not meaningful for this component preview. ContentList still uses its own published-only configuration. |

In all entry cases authenticate Admin first, load the exact entry under the existing authenticated entry-preview field ACL and active-provider rules, reject private Section/withdrawn provider/mismatched type as 404, and allow draft entries ONLY in this private response. For single reject Page/Section entries as the public Page resolver is separate. Derive slug/schema/fields from storage, never accept client field values, route URLs, slugs outside the typed target, HTML or arbitrary preview targets. Use public-filtered site options/menus and existing authenticated field-binding resolution. A single preview transaction captures the target/prior AST, entry/schema, settings, referenced DB parts, media and active-theme revision metadata; load verified immutable revision files for that captured digest. Do not mix a second independently read active selection into the render.

For a selected entry, content_slot receives its normal authenticated preview body: render its D02 entry Builder with is_preview=true when mode=builder and document exists, otherwise use the existing authenticated text-body renderer. Never render the shared template recursively as entry content. Private entry media use authenticated preview URLs, not public ACL grants. Public ContentList rows remain published-only even when the selected sample entry is draft. Without a selected entry, use a fixed server-owned `<div data-template-preview-placeholder>Preview content</div>` for an allowed content slot and leave route bindings unavailable with existing diagnostics. Non-entry targets have zero slots as enforced by Save; index permits at most one. No context selector UI is required for no-entry preview; existing route context may supply a sample entry.

Render referenced parts using typed DB-part precedence over verified active-theme parts, including nested references, with one shared cycle/depth<=3/expansions<=32 budget. Shadow a matching root part with the submitted draft only in the request-local graph so a draft self-cycle is rejected. Do not query unrelated parts or run persisted root instead of the draft. All Builder documents retain the existing 512-node limit, JSON validation and per-request output ceiling 512 KiB including slot and expanded parts. Use existing shared C-SEC fuel/HTML escaping and bounded renderer, not raw theme source injection. Missing parts follow the existing safe missing-part diagnostic/fallback, never load a file path supplied by the client. Public rendering behavior is unchanged.

### Mixed-part composition interface and budgets

The current Harbor helpers do NOT already implement a mixed DB/theme graph or shared fuel: `render_theme_parts_for_builder` compiles independent string-source DAGs and `CompiledCsecComposition::render` allocates a fresh environment. D03 explicitly adds the bounded preview-only adapter below; it must not silently reuse those independent calls as a claimed shared budget. Public caller behavior and existing `CompiledCsecComposition::render` signature stay unchanged.

In storage/overrides.rs build a request-local `PreviewPartSource` map whose variants are `Builder(BuilderDocument)`, `Theme(String)` and `Missing`; only reachable literal keys are loaded from the same captured snapshot/revision. The edited root shadows its exact key. Walk the graph once using an active canonical-key stack, edge occurrence depth and expansion count (root depth 0; at most 3 part edges and 32 expanded occurrences, including repeated references). Extract Builder edges from TemplatePart and theme edges from the validated C-SEC composition AST, not text searches. Graph discovery/validation has no MiniJinja execution or HTML injection. Missing nodes become existing missing-part diagnostics. Resolve the graph as contiguous theme composition segments separated by Builder AST boundaries, with a single mutable `PreviewCompositionBudget {fuel_remaining:u64=10_000, expansions:usize, stack:Vec<String>}` threaded through the storage/page/template_sec preview helpers; no fresh per-part fuel allowance. Memoization must not suppress graph edge occurrence checks or final output accounting.

In template_sec.rs add a preview-only safe compiler/render bridge: `render_preview_csec_fragment(name:&str, source:&str, context:Value, theme_sources:&BTreeMap<String,String>, trusted_builder_parts:&BTreeMap<String,String>, budget:&mut PreviewCompositionBudget) -> Result<String, &'static str>`. It validates the original theme AST/HTML with the existing C-SEC allowlist and composition-site validator. Flatten contiguous theme-to-theme edges per occurrence into ONE validated MiniJinja program using the existing composition compiler semantics; never pre-render a theme child independently of its theme parent. Parent set/with locals, repeated occurrences in different scopes and conditional execution therefore remain intact. Only an od_part edge crossing into a trusted Builder-origin fragment becomes a fresh 128-bit random nonce, not a callable/raw/safe variable; reject reserved compiler markers in source. Theme edges and Builder edges remain distinct after DB-over-theme resolution. After safe shell rendering and post-render contextual HTML/URL/CSS validation, replace only generated nonce sites with child HTML produced by these trusted preview renderers. A nonce may occur zero times when its conditional branch was not executed, once otherwise; reject multiplicity >1. Client values never supply resolved HTML or marker identities. Builder-origin forms can pass only through the existing sanitized/disabled preview renderer; theme source still cannot introduce forms/scripts or inject markup through attributes/URLs/CSS. Theme parts still forbid od_content. This bridge is private to D03 preview and does not broaden accepted package source or enable guest raw HTML.

Create each restricted environment with `set_fuel(Some(budget.fuel_remaining))`; render using pinned MiniJinja 3.0.5 `Template::render_captured`, then debit its `Captured::state().fuel_levels()` consumed count and obtain `Captured::output()`. These exact APIs were verified in the installed pinned crate source. Missing fuel tracking or exhausted/invalid accounting fails closed (400 for this preview), never resets to 10,000. Pass the same budget into every C-SEC theme segment; all graph counters are the prevalidated request graph's counters, not independently reset compiler counters. The existing restricted recursion limit remains. Builder nodes retain their per-document 512 cap and all renderers enforce 512 KiB intermediate and final output limits after each child insertion; final root length counts every duplicate inclusion and slot bytes. No minijinja dependency or feature upgrade.

Storage assembles each Builder node by passing already trusted child HTML to page::render_builder_with_template_context with is_preview=true; each contiguous theme segment uses the new bridge once. At a Builder boundary, bindings and any nested theme segment receive the authenticated server snapshot context, never MiniJinja-local variables from an enclosing theme frame. Builder AST has no MiniJinja expression scope. Contiguous theme descendants always inherit their actual lexical theme parent. Pre-rendering independent Builder children is permitted, but not splitting theme-to-theme edges; theme-only children in untaken conditional branches must not execute or raise strict-undefined errors. The storage traversal, not a public HTTP route, owns mixed recursion. The final root uses the same pathway and budgets. Add focused mixed-chain tests Builder -> theme -> DB Builder -> theme, theme -> DB precedence, edited part -> theme -> edited part cycle, repeated-edge depth/fanout accounting and two separately safe theme nodes whose combined fuel exceeds 10,000. Also require the existing parent-set-title regression below a Builder root, with-block shadowing, two occurrences under different locals and an untaken conditional containing an undefined-variable theme child. Test malicious theme source/attribute markers remain rejected and nonce substitution never treats arbitrary client strings as trusted HTML.

### Frontend and alternatives

Add `previewTemplateOverride(target, document, csrfToken, previewEntry?, expectedVersion?, signal?) -> Promise<HomepagePreview>` in api/builder.ts through client.ts. BuilderWorkspace chooses this ONLY for the shared-template target; entry Page, Section and pre-S03 homepage retain their separate APIs. Send the current unsaved AST, typed target and current saved version when one exists. Existing 401/412 handling keeps local AST/target and dirty state; do not reload or Save implicitly. Use AbortSignal and the existing sequence/revision/account checks so a late response cannot replace a newer draft/account/target. Keep preparePreviewMarkup private raster fetching with its MIME/count/byte limits and `<iframe sandbox="">` (no allow-scripts/allow-same-origin). The iframe receives the same document/component markup shape as existing Builder preview; it is not a claimed screenshot of the public route.

Reject the alternatives of saving temporarily, restoring old role/scope aliases, adding a generic public preview URL, and requiring a DB row before Preview: these either mutate public state, revive an obsolete contract, expand exposure or prevent previewing a new template.
