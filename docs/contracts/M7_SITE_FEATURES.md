### Trusted document normalization algorithm

New server `document.rs::normalize_public_document` returns `SafeDocumentParts {body_attributes, body_fragment, authorized_styles}`. Input is a typed composition of individually C-SEC-validated provider fragments and trusted typed core-generated markup. Keep those origins distinct in internal SafeProviderHtml/CoreHtml types: core contact/video markup is allowed only through its typed renderer, never through a provider raw-string bypass. Do not broaden provider FORBIDDEN_TAGS or run provider-only form prohibitions against final trusted core forms. No arbitrary uploaded HTML is accepted. Maximum rendered document4MiB, one linear bounded scan. Tokenize HTML delimiters case-insensitively, honor quoted attribute values and comments; style content uses HTML raw-text termination at the actual case-insensitive end-style tag (a CSS string containing end-head is not a head delimiter). Reject script/object/base/event-handler tokens through existing C-SEC. Do not regex-split HTML or use literal body search.

A fragment contains NO html/head/body/doctype tokens (including orphan opening/closing envelope tags); otherwise reject to the documented fallback. Accept a validated fragment OR one optional doctype followed by exactly one html envelope with at most one head and exactly one body; reject duplicate/nested envelopes, unclosed comments/quotes/raw-text, head after body or non-whitespace outside the envelope. For head tokens keep only authorized style/style-link tokens already permitted by C-SEC; discard title, metadata and canonical/robots/link projections so the core can emit exactly one typed SEO set. Body attributes must pass the existing safe attribute allowlist; no style/link permission is added by this normalizer. Serialize a fresh core html/head/body document containing preserved safe body attributes/content and authorized styles, then compose validated header/footer inside body once. No user-supplied markup is promoted to a trusted head token.

Malformed/oversized envelope produces a stable diagnostic and uses core default template rendering for that route, retaining escaped content; if default rendering cannot succeed, return a generic noindex503 page. Do not silently render malformed input or lose the underlying stored template/layout. Admin diagnoses the failed provider/template; change remains editable. Tests cover uppercase/mixed-case wrappers, body attributes, comments/quoted delimiters, style strings containing end-head, duplicate envelopes, forged canonical/title tags, malformed raw-text and output limits. Routes must use this boundary for both current and legacy full-document templates; the old literal compose helper cannot remain as an alternate bypass.
