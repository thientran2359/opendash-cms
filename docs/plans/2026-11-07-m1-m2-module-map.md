# Đối chiếu module M1/M2 trước khi nhập mã

Ngày 07/11/2026. Đây là đề xuất triển khai cho bước 3 của [kế hoạch nhập mã](README.md). Phạm vi gồm M1 Auth/Builder, M2 plugin ABI v1, dữ liệu nâng cấp và binary Windows. CPT/Media M3, builder nhiều tầng, chuyển kho gói sang filesystem, nâng dependency và phát hành nằm ngoài lượt nhập này.

## Hai mốc đối chiếu

Đích là cây Git tại `0ec91ec2cbdf3f6b3cdecf31ece32406398b4f7a`. Nguồn là cây làm việc tại HEAD `7a519d0`, gồm cả file mới và thay đổi chưa commit. Đã tính lại fingerprint theo [báo cáo nguồn](../verification/2026-11-07-m1-m2-source-baseline.md), khớp `4a6efb825a11b6dcb5d6b505c8a556a0aa53bf6c9f5a187d41e298ee73e8b091`. Trước khi nhập, kiểm tra lại fingerprint nếu repo nguồn còn được chỉnh.

Đã so danh sách và nội dung các file nguồn với `git ls-tree` và `git show` tại commit đích, sau đó đọc các điểm gọi giữa module. Trong bảng, đường dẫn mã ở nguồn tính từ gốc repo nguồn. Tại đích thêm tiền tố `cms/`, trừ tài liệu dự án và thư mục website. Các tiêu chí dưới đây dành cho **bản tích hợp sau này**. Kết quả 28 unit test và 4 bộ smoke đã ghi thuộc bản nguồn.

## Thứ tự nhập và điều kiện để chuyển bước

1. **Dựng ngược được bộ nguồn trong layout đích.** Đưa manifest/lockfiles, core, migrations/fixture, SDK và ví dụ vào vùng tích hợp riêng. Đối chiếu byte ba SQL và hash fixture với nguồn. Build Admin và ZIP mẫu để các macro Rust có đủ input.
2. **Ghép server và Admin theo các phụ thuộc thật.** Main, router và AppState nguồn tham chiếu plugin manager ngay khi khởi động; đưa M1/M2 vào cùng bản build trước khi kiểm chứng theo chức năng. Giữ `SitePaths`, route đích và chuỗi migration. Chạy fmt, workspace tests và release build với lockfile.
3. **Kiểm chứng tại đích bằng site tạm.** Chạy lại bốn bộ smoke nguồn. Kiểm tra riêng hai nhóm chỉ có ở đích: (a) binary khởi động từ thư mục khác, lần cài đầu và hai biến ghi đè đường dẫn, (b) cả hai URL Admin, asset MIME/404 và health với SQLite. Xác nhận preview giữ bản đang công khai, Lưu tồn tại sau restart, Editor bị chặn cài gói, plugin lỗi vẫn cho Admin vô hiệu hóa.
4. **Ghi bằng chứng đích trước khi chuyển sang M3.** Lưu lệnh, kết quả, giới hạn và các test scaffold được giữ hoặc thay tương đương. Số lượng test có thể đổi khi hợp nhất; tiêu chí là các hành vi của cả hai mốc còn được kiểm tra.
