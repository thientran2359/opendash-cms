## Changes Implemented

1. **Runtime config & recovery state (`cms/crates/opendash-server/src/config.rs`, `main.rs`, `app.rs`):**
   - Added `RuntimeConfigV1::load(&paths)` with strict precedence (`defaults < config/site.json < explicit env overrides`) and `READY.json` safe-mode detection.
   - Added `RecoveryState` enforcement across:
     - Public routes (`app.rs`): injects `X-Robots-Tag: noindex, nofollow` while `safe_mode` is active.
     - Anonymous contact submissions (`routes/contact.rs`): returns `503 Service Unavailable` while `safe_mode` is active.
     - Plugin execution (`plugin/manager.rs`): blocks `execute_plugin_action` and `run_plugin_with_mode` with `503 Service Unavailable` (`safe_mode`).
     - SMTP delivery (`smtp.rs`): blocks `execute_claimed_attempt` and `send_test_email` while `safe_mode` is active.
2. **Admin restore & activation endpoints (`cms/crates/opendash-server/src/routes/operations.rs`, `app.rs`):**
   - `POST /api/admin/operations/restore-uploads`: streams `application/octet-stream` in 64 KiB chunks up to `MAX_ENCRYPTED_ARCHIVE_BYTES` (`4297064448` bytes) into private staging.
   - `POST /api/admin/operations/restores`: spawns `--operations-worker restore` (`202 Accepted`) to stage and publish a restored site into `backups/restored/<job_id>/` with `READY.json`.
   - `GET /api/admin/operations/recovery/status`: reports `safe_mode`, `smtp_enabled`, `ready_marker`, `site_root`, and `expected_generation`.
   - `POST /api/admin/operations/recovery/activate`: requires Admin CSRF/Origin, verifies current Admin password and matching `READY.json` generation, persists `recovery_safe_mode: false` in `config/site.json`, clears runtime `safe_mode`, and keeps SMTP disabled until reconfigured.
3. **Admin UI (`cms/admin/src/api/operations.ts`, `cms/admin/src/features/operations/RestorePanel.tsx`, `cms/admin/src/App.tsx`):**
   - Added `RestorePanel` for `.odbackup.age` upload/restore and operator safe-mode activation.
