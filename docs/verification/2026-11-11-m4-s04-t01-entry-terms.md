## Contract and data protection

Term associations are site-owned with table `entry_terms(entry_id,term_id)`, PK on the pair, cascading entry deletion and restricted term deletion, plus inverse index. Migration `0014_entry_terms.sql` follows Forge-owned `0013_builder_homepage.sql` (#78), which **must merge first**. Never modify already released `0012_taxonomy_terms.sql` or apply 0014 to a production site before 0013 is available. Inactive CPT providers must not lose links. Term ID validation rejects duplicates, invalid/missing terms, and over 32 categories or 64 tags per entry.

Create/update on Post, Page, CPT accept optional `term_ids`. Omitted on update **preserves links** (legacy clients); `[]` removes all. Content fields, membership and entry version commit or roll back as one transaction; stale `If-Match` returns 412 without mutation. Publish/unpublish shares entry version and never implicitly clears memberships. Admin and Editor may assign existing terms under existing entry write permissions. Admin manages taxonomy terms; a term linked from an entry cannot be deleted.

List filters may include `category_id`, `tag_id`, and `include_descendants=true`. Category and tag combine via AND, with category descendants computed from the **current parent tree**. Queries must filter **before** `LIMIT/OFFSET` without duplicated rows; public filtering must also apply the existing published-only policy and media ACL.
