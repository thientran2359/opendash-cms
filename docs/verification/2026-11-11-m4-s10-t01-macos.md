## Reproduction from pinned source

Use a clean checkout pinned to exactly
`ac2aad5af06bf383bd1af25704ac1a7d95cb06d0`, with this runner
available, and an independent Cargo target directory:

```sh
export PATH="$HOME/.cargo/bin:$HOME/.nvm/versions/node/v24.22.2/bin:$PATH"
npm ci --prefix cms/admin --prefer-offline --no-audit
npm run typecheck --prefix cms/admin
npm run build --prefix cms/admin
cargo fmt --manifest-path cms/Cargo.toml --all -- --check
export CARGO_TARGET_DIR="$PWD/cms/target"
cargo build --manifest-path cms/Cargo.toml --locked --release
cargo test --manifest-path cms/Cargo.toml --workspace --locked --release
python cms/scripts/m4_release_macos.py \
  --binary cms/target/release/opendash \
  --m3-binary PATH_TO_M3_d2b6bfe_MACHO_X86_64 \
  --browser "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --release-sha ac2aad5af06bf383bd1af25704ac1a7d95cb06d0
python cms/scripts/check-plans.py
python cms/scripts/check-plans.py --self-test
python cms/scripts/check-standards.py
python .agents/scripts/check-agent-artifacts.py
git diff --check
# Additional M3 foundation security/plugin checks, from cms/ directory:
cd cms
python scripts/windows_auth_smoke.py --binary target/release/opendash \
  --baseline-db fixtures/baseline_0001.sqlite --baseline-binary PATH_TO_PRE0009_MAC_BINARY
python scripts/windows_plugin_smoke.py --binary target/release/opendash
python scripts/windows_plugins_browser.py --binary target/release/opendash \
  --browser "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
python scripts/windows_kernel_smoke.py --binary target/release/opendash
```

The runner requires macOS x86_64, exact matching M3 binary checksum and
`git rev-parse HEAD == --release-sha`; it refuses a mismatched source.
Do **not** use `--skip-regressions` for acceptance: it explicitly labels
the 15 regressions `NOT_RUN`. Raw logs and release binaries remain in
the agent's local evidence directory, not committed.
