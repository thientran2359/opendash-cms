## G4 verified behavior

`GET /api/admin/library` provides session-protected, `no-store` site-owned Section metadata and canonical active V2 theme role descriptors, never private Section AST, manifest bytes or cloud resources. Editors see permitted Section metadata but not theme descriptors. Existing scoped Section-document API remains the only source of private AST. `#/appearance/library` replaces the disabled stub, surfaces unsupported theme roles with reason and links to edit site-owned Sections.

Within any authorized scoped Builder, "Chọn Section" copies the selected Section AST into the destination, generating unique fresh IDs for Section, row, column and element nodes; it does **not** change source Section or destination until explicit Save. Existing node/list-size validations and unresolved-provider preservation checks remain enforced. Source-only media is private; a copy saved to an unpublished Page keeps media private, and a published Page grants public access only through its explicit published saved design. Editor cannot mutate homepage/global overrides.

Theme apply uses a visible confirmation plus the **atomic** `/api/admin/library/apply/{role}` flow, with CSRF/Origin, Admin authorization, If-Match override CAS and active revision+digest checks within one SQLite writer transaction. Cancel does not write; stale override **412**, concurrent theme switch **412**, and unsupported roles are not exposed as working actions. Owner notes and status are retained across the successful catalog refresh. Switching theme providers does not modify source/copied AST, and the previous provider's descriptors disappear.
