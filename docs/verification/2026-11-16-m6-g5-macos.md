## Acceptance được kiểm trực tiếp

Test `m6_s08_t01_plugin_e2e.rs` chạy với binary/server và SQLite thật trên macOS, bao gồm:

1. Cài ZIP manifest schema v2 với plugin-owned CPT `job_posting`, các field `company`/`salary`, eligibility `category`/`tag`; tạo category, kiểm schema UI v1 và action `host_call` của Editor gọi HTTP egress mock có scope trên loopback.
2. Cài `veto-guard` với `content/before_save`, xác minh lưu entry bị veto HTTP `422`; tắt guard rồi lưu entry thành công HTTP `201`.
3. Kiểm Builder `PluginBlock` AST giữ được node khi provider không còn trong registry, và owner-neutral setting/template override trong SQLite.
4. Tắt plugin, dừng server, chụp snapshot site, khởi động lại, xác nhận Editor đọc/sửa entry khi plugin tắt và action plugin bị chặn; bật lại rồi action chạy thành công.
5. Sửa nội dung sau snapshot, dừng server, khôi phục **toàn bộ site snapshot**, chạy lại **cùng binary** và xác nhận tiêu đề cũ cùng plugin-owned setting/template vẫn còn. Đây là restore theo snapshot + matching binary; không thực hiện in-place SQLite downgrade hoặc chạy binary phiên bản khác.

Smoke Python bổ sung xác nhận package validation, quyền Admin/Editor, CSRF/Origin, limits, disable/enable và KV persistence bằng plugin mẫu độc lập. Chạy Chrome trực tiếp chỉ kiểm màn hình Admin và đăng nhập, không khẳng định toàn bộ workflow UI plugin đã được điều khiển tương tác.

## Worker cancellation reliability fix — bổ sung Mac Intel ngày 2026-11-16

Chủ dự án trực tiếp cấp phép Harbor sửa `cms/crates/opendash-server/src/plugin/tests.rs` để xử lý blocker của #188. Bản sửa đặt trên branch riêng `fix/harbor-m6-worker-cancellation`, base `main@c3b5fa6895d413800a2ac2b3cc7076950345bdb4`, **không** sửa runtime hoặc report Windows và **không** thay thế bằng chứng same-full-SHA `4841a0b` ở các mục trước.

- **Nguyên nhân test thiếu ổn định:** sau khi spawn invocation, test cũ `sleep(300 ms)` rồi kiểm `active_workers()==1`; dưới áp lực chạy suite song song, nó có thể quan sát worker trước khi mock HTTP request thực sự đến. Test mới dùng `tokio::sync::oneshot` báo hiệu **sau khi mock HTTP server đọc được request**, `tokio::select!` cùng timeout tối đa 10 giây và chẩn đoán invocation kết thúc sớm. Chỉ sau tín hiệu thật mới assert worker active, huỷ task và xác minh worker=0 + bốn permit được trả. Không nới deadline sản phẩm, tắt test hay bỏ kiểm chứng cleanup.
- **PASS** trên macOS Intel: `cargo test --manifest-path cms/Cargo.toml -p opendash-server --bin opendash test_worker_termination_on_caller_cancellation --locked -- --nocapture` (1/1); `cargo test --manifest-path cms/Cargo.toml -p opendash-server --bin opendash --locked --quiet -- --skip paths::tests::fresh_install_uses_executable_directory_when_launched_from_elsewhere` (87/87, **3 lần**, dùng thư mục TMPDIR riêng); `cargo test --manifest-path cms/Cargo.toml --test m6_s08_t01_plugin_e2e --locked -- --nocapture` (1/1). Admin `npm ci` + build và check-standards/self-test, plans, agent artifacts bằng Python 3.11.18 PASS.
- **Full workspace hiện tại chưa PASS, lỗi ngoài file sửa:** trên `main` mới có M8 tests, `TMPDIR` mặc định Mac đi qua symlink `/var` làm 8 test M8 paths/operations FAIL; trỏ trực tiếp `/private/tmp` giúp các test đó PASS nhưng secrets ACL test FAIL vì yêu cầu chmod 0700 trên thư mục do root sở hữu. Với `TMPDIR` trỏ thư mục riêng **0700 thuộc user** (trong `cms/target/m6-test-tmp`), server chạy **87 passed/1 failed** vì `paths::tests::fresh_install_uses_executable_directory_when_launched_from_elsewhere` (FAIL kể cả chạy riêng; `SitePaths::resolve_from` trả đường dẫn checkout thay vì temp fixture). Khi chỉ loại trừ test paths ấy, các unit tests và nhiều integration suites PASS, nhưng M8 `r2_cancel_restore_kills_worker_and_preserves_source_and_previous_restores` vẫn FAIL bởi `memory_limit_failed: setrlimit(RLIMIT_AS) failed with -1` trên Mac. Hai lỗi này ở M8/path harness, **không thể suy ra đã đạt full workspace hoặc fix #188 G5**; cần owner của các file tương ứng xử lý và kiểm lại trên Mac.
- `cargo fmt --all -- --check` trên baseline `main` cũng trả nonzero với nhiều khác biệt format đã tồn tại ngoài file ownership; không chạy formatter tự động toàn repo. `git diff --check` ở nhánh fix PASS.

**Trạng thái:** test cancellation từng FAIL khi chạy song song nay được kiểm PASS ở server suite (sau khi loại trừ lỗi paths độc lập), nhưng **#188 vẫn Open / Project In progress** cho đến khi các gate còn lại được owner xác nhận hoặc xử lý.
