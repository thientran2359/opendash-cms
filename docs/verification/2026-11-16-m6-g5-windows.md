## Browser harness diagnosis and limits

The unmodified historical Python smoke harness sets `OPENDASH_PORT=0`, which this source build rejects (`400 Bad Request: port phải khác 0.`), so **the unmodified script FAILS at startup**. The local-only adapter changes just the launch port to an OS-assigned nonzero loopback port and adjusts a moved sample ZIP path in the browser script. The adapted HTTP smoke passes; this does **not** mean the original historical script passed.

The initial local browser test stalled on outdated assumptions: the Admin auto-selected the uploaded plugin (the `Chọn chạy` label had already changed) and, after restart, its React guest panel could render briefly before session restoration. An assertion against the plugin name was also inaccurate because the Declarative UI renders the plugin ID and action title. The scratch harness was corrected to wait for the selected state, the actual schema, and persisted server state; upload HTTP status is checked explicitly. A separate Chrome teardown delay occurred after browser assertions; the final run let the Playwright context manager handle teardown and **returned exit 0**.

The successful browser probe was a **local scratch script in ignored `cms/target/`**, not a versioned test. Its SHA-256 was `40c24a3334c045d5cbfa2cfd8033a06ea27e393dea6d0488fa6ed4648def6d88`. The local port adapter was also unversioned (SHA-256 `a38fb9f2e1c71b3a1b3893d265f06f7a23196d051624c839f6f707e5a08f637b`). The Rust M6 E2E test is tracked in the repository and is the repeatable cross-module acceptance test. The historical native Chrome `windows_plugins_browser.py` test was not independently completed to PASS at this source commit.
